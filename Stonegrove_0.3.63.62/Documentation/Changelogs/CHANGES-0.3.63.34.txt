STONEGROVE 0.3.63.34 - Multiplayer performance and client fixes

World ticks have priority over queued requests, with FIFO ordering for normal requests and a deadline-based tick schedule. Private immutable entity snapshots, packed rows and global sections are reused between players; unchanged entity fields, guards and station/cave sections are omitted where supported. Guard deltas are negotiated by the new clients; older clients retain full guard snapshots. Caches use weak references and reset for mutations/room changes. JSON serialization uses a shared output buffer, bounded key quoting and faster string scanning, preserving the existing packed save/network format. Lua-encoded multiplayer responses are forwarded directly through HTTP. Negotiated gzip reduces multiplayer bandwidth, with native Windows client decompression and plain-JSON fallback.

Unchanged camp XP/heartbeat writes are coalesced, with immediate writes for XP/owner changes. Short-lived XP baselines and revision-cached Religion baselines avoid repeated character-save decoding. Character writes/deletion invalidate caches. SQLite connections close explicitly while preserving commit/rollback behavior. The pending HTTP connection queue accommodates group reconnects. A separate-process, isolated 30-account load-test tool is included in Server/load_test_30.py; see Server/PERFORMANCE.txt and the measured report.

Large Fish now unlock at Fishing 7. Oak poles catch Small Fish at levels 5-6; inventory space checks use the actual fishing tier. Large Fish produce 2-5 raw fillets, increasing with Cooking level from 7 to 99. Tooltips updated.

The launcher remembers username and successfully authenticated password for the same server. Passwords are encrypted with Windows DPAPI, rather than stored as plaintext. Failed logins retain the previously successful password; changing server prevents reuse. Both developer and alpha launchers support this.

Double-click a shop item within 0.35 seconds to buy one through the existing purchase handler. Prices, grading, stock, funds and inventory checks are preserved. Different items/shops, delayed clicks and right-clicks do not trigger a purchase.

Previous editor Bag Keeper, bag recovery, graded rune bank, Religion/bonfire, grave/cave persistence and all prior content fixes remain included. Update server and both clients together. No production accounts or saves were modified. Test measurements describe this local machine, not guaranteed Render/Cloudflare capacity or 100-player support.
