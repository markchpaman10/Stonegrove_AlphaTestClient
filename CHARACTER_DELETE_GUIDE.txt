STONEGROVE 0.3.63.13 — Launcher character deletion

Added Delete beside each occupied account character slot in both developer and alpha launchers. Empty slots have Create character and no Delete action. Deletion opens a confirmation screen showing the chosen character name and slot, Cancel and DELETE CHARACTER. Escape cancels. Nothing is deleted until the confirmation button is clicked.
Confirmation explains that character progress, inventory and camp are removed; the account and other character slots remain. Added Refresh characters in the ordinary character-slot screen to reload stale slot information. Launcher buttons are blocked while a request is in flight; duplicate deletion cannot be queued. Pending/busy profile saves block deletion.
Added authenticated DELETE /v1/characters/{slot}, requiring the current revision and character name. Ownership comes from the authenticated account. Invalid slots, stale names/revisions, already-empty slots and active sessions are rejected. Same-account character save/join/delete operations serialize without blocking requests from unrelated accounts.
Successful deletion removes the selected character row, its camp ledger and camp request receipts, in-memory identity/name caches and any retired shared-world actor/camp. The account, session and other character slots are retained. Deleting a character still active in shared-world simulation or presence is rejected until it returns to the launcher on all computers and its session ends.
A deleted-slot revision marker is persisted. The freed slot is listed as empty with the updated revision and can immediately be used to create a new character. Old saves, backups and stale delete requests cannot overwrite or delete its replacement. Legacy import identifies empty slots by name and uses their current revision.
Before submitting deletion, local pending/save/race files are copied to .deleted-{revision}.backup files. Failed server requests preserve the active local files. After confirmed success, active local pending/save/race files are cleared and the slot list refreshes. Archived files remain available for manual inspection and are not automatically restored.
Existing accounts/saves migrate by adding only the deleted_characters table when the server starts. No production database or account was edited during development. Update server and clients to 0.3.63.13 together.
